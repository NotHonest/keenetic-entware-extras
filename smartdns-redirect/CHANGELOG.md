# Журнал изменений

Все заметные изменения `smartdns-redirect` описаны здесь.

Формат: [Keep a Changelog 1.1.0](https://keepachangelog.com/en/1.1.0/)
Версионирование: [Semantic Versioning 2.0.0](https://semver.org/spec/v2.0.0.html)

## [0.6.5] - 2026-08-30

### Исправлено
- В зависимости пакета добавлен `bind-dig` — `watchdog.sh` использует `dig` для проверки доступности upstream

### Изменено

- Руководство пользователя: `REDIRECT_MODE` добавлен в таблицу параметров

## [0.6.2] - 2026-07-31

### Исправлено
- **`disable` теперь полностью убирает следы**: удаляет хук NDM netfilter.d и комментирует
  задание cron watchdog. Раньше удалялись только правила iptables и символическая ссылка init.d,
  оставались устаревший хук и активная запись cron.
- **`enable` восстанавливает инфраструктуру**: заново создаёт символическую ссылку хука NDM и раскомментирует
  задание cron watchdog (без дублирования строк).
- **Упрощён вывод `status.sh` при отключении**: при самоотключении показывается короткий текст
  «disabled (правила iptables удалены, перехвата DNS нет)» вместо полного
  вывода конфигурации, правил и upstream с вводящими в заблуждение отметками ✓/✗.

### Изменено
- `status.sh`: строка блокировки DoT в секции Mode больше не показывает отметку ✓
  (это отображение конфигурации, а не проверка во время работы).

### Удалено
- Поле `dot_block` из вывода JSON — избыточно рядом с `redirect_mode`
  (`force` → всегда включено, `local` → всегда выключено).

### Добавлено
- **Статус cron watchdog** в текстовом и JSON-выводе `status.sh`: показывает `Watchdog: cron */5 min ✓`,
  когда задание активно, и `(no active cron job) ✗`, когда его нет или оно закомментировано.

## [0.6.1] - 2026-07-30

### Изменено
- `status.sh`: цветные отметки статуса и жирные заголовки секций через цветовую систему `lib/status.sh`; поддержка флагов `--color`/`--no-color`
- `status.sh`: `check_rule()` переписан с 4 повторяющихся веток case (−50 строк) на единый API `status_line_cont()`

## [0.6.0] - 2026-07-30

### Добавлено
- **Параметр конфигурации `REDIRECT_MODE`** — `force` (по умолчанию, перехват всего DNS :53 +
  блок DoT :853) или `local` (перехват только DNS на IP роутера, внешний DNS проходит
  дальше, DoT не блокируется). Для устройств IoT или корпоративных ноутбуков с жёстко заданным DNS.

## [0.5.0] - 2026-07-29

### Добавлено
- **Блокировка DoT в режиме `force`**: DNS-over-TLS (порт 853) от клиентов LAN блокируется
  через iptables FORWARD REJECT вместе с DNAT :53. Клиенты не могут обойти
  SmartDNS прямым DoT к внешним резолверам (8.8.8.8:853, 1.1.1.1:853 и т. д.).
  Правила IPv4 и IPv6. Watchdog следит за правилами блокировки DoT.

### Удалено
- Параметр конфигурации `DNS_STRICT` — заменён на `REDIRECT_MODE` (force/local).

## [0.4.3] - 2026-07-28

### Изменено

## [0.4.2] - 2026-07-27

### Исправлено
- **Состояние parent-disabled в `status.sh --json`**: когда родительская служба (smartdns-geo-conf)
  отключена, JSON теперь возвращает `enabled:false` — webui больше не показывает 🔴 «Failed»
  для состояния, которое не является сбоем

### Изменено
- **Подробности parent-disabled в `status.sh --json`**: человекочитаемые поля `depends_on` и
  `action` (было: сырое `parent_disabled: "smartdns-geo-conf"` / команда CLI)
- **Проверки `status.sh --json` при отключении**: проверки во время работы (`running`, `upstream`,
  `rules`) теперь возвращают `"skip"` вместо `"fail"`, если служба отключила себя сама или отключена родителем

## [0.4.1] - 2026-07-27

### Добавлено
- `watchdog.sh`: проверка наличия S38 — ранний выход, когда SmartDNS отключён
  (S38 переименован командой `S37smartdns-conf disable`); watchdog больше не борется
  с намеренной остановкой
- `netfilter-hook.sh`: та же проверка наличия S38 — правила iptables не восстанавливаются,
  когда SmartDNS отключён намеренно

## [0.4.0] - 2026-07-27

### Добавлено
- Автоматическое предотвращение утечки DNS по IPv6: настройка пользователем не нужна
  - Авто-DNAT: если у SmartDNS есть bind IPv6 и у br0 есть глобальный IPv6 →
    ip6tables DNAT на SmartDNS (весь DNS IPv6 через SmartDNS)
  - Авто-REJECT: иначе → ip6tables INPUT REJECT с
    icmp6-port-unreachable (мгновенный запасной путь Happy Eyeballs на DNAT IPv4)
- Автоопределение `can_dnat_ipv6()`: проверяет ip6tables, IPv6 на br0 и bind SmartDNS
- `status.sh`: отображение режима IPv6 — `dnat`, `reject` или `none` (текст и JSON)
- `status.sh`: поле `dnat_target_v6` в выводе JSON в режиме DNAT
- `watchdog.sh`: проверяет правила IPv6 (DNAT или REJECT) по автоматически определённому режиму

### Изменено
- Параметр конфигурации `ENABLE_IPV6` удалён — обработка IPv6 полностью автоматическая
- Устаревшее `ENABLE_IPV6=yes` в config.conf пользователя даёт предупреждение об устаревании
- `del_all_rules()` теперь также убирает правила IPv6 filter INPUT REJECT,
  а не только nat PREROUTING
- JSON `status.sh`: поле `ipv6` изменено с `"yes"/"no"` на
  `"dnat"/"reject"/"none"`

### Удалено
- Параметр `ENABLE_IPV6` из `defaults.conf`
- Вспомогательная функция `ipv6_enabled()` (заменена на `can_dnat_ipv6()`)
- `add_rule_if_missing_v6()` (заменена на `add_v6_dnat_rule()`)

- `status.sh`: поле `"enabled"` в выводе JSON; в текстовом режиме показывается предупреждение «⚠ Disabled»,
