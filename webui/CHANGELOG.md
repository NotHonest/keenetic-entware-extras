## [Не выпущено]

Изменения этого форка. В пакеты фида 0xkee они не входят. Номер версии не менялся.

### Добавлено
- Экран сценария на `/custom/` (`static/scenario.js`): зона `eas`, `ROUTE_OUT` — интерфейс провайдера, `ROUTE_IN=br0`. Кнопка пишет конфиг geo-split, только если эти поля отличаются. Приоритет соединений Keenetic не меняет
- `GET /api/geo-split/tunnel-check` — проверка, проходит ли трафик через интерфейс основного маршрута или через `?dev=`. Только чтение
- `GET /api/geo-split/ladder` — лестница соединений: кто основной, кто проходит `ping-check`, кто ждёт, и последние 10 переходов маршрута и DNS. Без curl. Карточка сценария обновляет эти строки примерно раз в 30 секунд и не повторяет при этом `route-check` и `tunnel-check`

### Изменено
- Подписи панели, карточек и диагностики на русском

## [0.39.1] - 2026-10-31

### Исправлено
- **Несовпадение Origin при CSRF** — штатный бэкенд авторизации NDM отклоняет POST с `Origin: http://<IP>:8080` (ожидает порт 80). В location `/auth` и `/rci/` добавлена подмена `proxy_set_header Origin/Referer`, которая убирает нестандартный порт. Исправляет 403 при входе и вызовах RCI API
- **proxy_bind 127.0.0.1** — описан как необязательная мера при разборе проблем с conntrack TCP (src=dst=LAN_IP); на практике не нужен — уровень безопасности 6 (LAN) работает правильно и без него

## [0.39.0] - 2026-10-28

### Изменено
- **Автопатч для неизвестных enum** — `patch-stock-ui.sh` теперь сам определяет семейство патча по архитектурным маркерам (`signal`/`setter`) и применяет патчи с любым именем enum, извлечённым во время выполнения. Файлов vN.sh на каждый enum больше нет — переименования минификатора не требуют никаких действий. При любой ошибке патчи откатываются к чистому штатному бандлу
- **Удалены v1.sh–v8.sh** — все 8 статических обёрток наборов патчей заменены динамическим автоопределением. Логика семейств сохранена в `families/signal.sh` и `families/setter.sh`
- **Формат `.patch-state`** — добавлены поля `PATCH_ENUM`, `PATCH_FAMILY`; `PATCH_SET` теперь содержит `auto-signal` или `auto-setter` вместо `v1`–`v8`
- **`stock-webui-check.sh`** — рекомендации обновлены под автопатч (больше не предлагает создавать vN.sh)

### Исправлено
- **Подписи интерфейсов не разрешались** — туннельные интерфейсы (nwg, awg, ovpn) часами могли показываться сырыми именами устройств Linux вместо человекочитаемых подписей. Причина: `loadIfaceMap()` запускался без ожидания (гонка при первой отрисовке), а его promise кэшировался на всю сессию страницы (устаревшая карта). Исправление: `loadIfaceMap()` ожидается до первой отрисовки и на своём, и на штатном дашборде; добавлена реактивная инвалидация — если в загруженной карте встречается неизвестное туннельное устройство, планируется повторный запрос с задержкой (в устойчивом состоянии лишних запросов нет)
- **postrm: снова включить штатный S80nginx при удалении** — `chmod +x /opt/etc/init.d/S80nginx` возвращает бит выполнения (postinst снимал его, чтобы не было конфликта портов); служба при этом не запускается

## [0.37.0] - 2026-08-04

### Добавлено
- **Сведения о системе: температура CPU** в полосе заголовка sysinfo (между загрузкой CPU и RAM).
  Читается `/sys/class/thermal/thermal_zone*/temp`, зона CPU определяется по `type`.
  Путь thermal zone находится один раз за жизнь воркера (после пробы накладных расходов нет).
  Мягкая деградация: элемент скрыт, если у SoC нет thermal zone.
- **Пороги температуры по SoC** из даташитов — таблица `THERMAL_SPECS` сопоставляет
  подстроку типа зоны с warn/crit/Tj_max. Известные SoC: MT7621/MT7628/MT7620 MIPS
  (105°C), MT7622BV ARM (105°C), MT7986/MT7981 Filogic (115°C), Qualcomm IPQ (110°C).
  Также распознаются зоны `soc-thermal`. Для неизвестных SoC — осторожные значения по умолчанию (100°C).
  Пороги вычисляются один раз при инициализации и уходят в ответе API как `cpu_temp_limits`.
- **Число ядер CPU кэшируется на воркер** — upvalue `_cpu_cores` не перечитывает
  `/proc/cpuinfo` на каждом опросе (число ядер во время работы не меняется).

## [0.25.5] — 2026-06-17

### Исправлено
- **Ложные красные индикаторы**: бейджи статуса больше не показывают красные «Stopped» / «Error»,
  если служба на самом деле работает, а API на миг недоступен. Новый бейдж из 5 состояний:
  зелёный (работает), жёлтый (предупреждения), серый (остановлен/отключён), синий (устарело / нет данных),
  красный (только настоящий сбой: enabled=true, а процесс мёртв).
- **Stale-while-revalidate**: при ошибке запроса предыдущий бейдж сохраняется 30 с, прежде чем
  показать нейтральный индикатор «stale». Мигание из-за кратких сетевых сбоев убрано.
- **Ложный «Stopped» при холодном старте**: заглушка Lua изменена с `running:false` на
  `status:"pending"` — фронтенд больше не показывает ложный «Stopped», пока кэш прогревается.
- **Stopped и Failed**: `enabled:true` + `running:false` = красный «Failed» (сбой);
  `enabled:false` = серый «Stopped» / «Disabled» (так задумал пользователь). Раньше любой
  `running:false` был красным.
- **Подавление вспышки переключателя**: бейдж «Failed» больше не мигает при перезапуске службы,
  пока активен быстрый опрос.

- `updateCardAccent(id, state)` — упрощённый API на строках.

## [0.20.1] - 2026-06-07

### Исправлено
- **Штатный сайдбар ломался после визита на свою страницу** (критично): причина в том, что
  `setupRestore()` вызывался только при `injectSidebar=1`. При конфигурации по умолчанию
  (`injectSidebar=0`) обработчик перехвата клика и MutationObserver не
  регистрировались — после открытия своей страницы кликом по карточке дашборда не было
  способа убрать iframe, когда нажимали штатный сайдбар. Исправление: `setupRestore()`
  теперь вызывается в `tryInject()` безусловно.
- **Содержимое не восстанавливалось при удалении iframe**: `removeIframe()` теперь возвращает `display`
  дочерним элементам содержимого Angular, которые скрывал `showInContent()`. Раньше
  iframe удалялся, а router-outlet Angular оставался с `display:none`.
- **Назад в браузере со своей страницы**: `showInContent()` теперь кладёт состояние в историю
  (тот же URL, маркер `{__ew}`). Обработчик `popstate` только на выход в `setupRestore()`
  убирает iframe по «Назад» и не показывает его снова по «Вперёд» (нет конфликтов с Angular).
  Наблюдатель смены маршрута тоже убирает iframe как страховку.
- **Вкладки своей страницы: поддержка назад/вперёд**: `switchTab()` в app.js теперь использует
  `history.pushState()` вместо `replaceState()` при смене вкладки, со слушателем `popstate`,
  чтобы применять маршрут из hash при навигации браузера.
